•	Overview: This SQL script creates a small event-management schema for a race-day application. It defines six core tables to model users (organisers/participants), events, event categories, route metadata, enrolments and results. The DDL includes identity primary keys, foreign-key relationships and sensible defaults so the schema is ready for development and testing.
•	Data model and constraints: Relationships are enforced via foreign keys: Event.OrganiserID → User.UserID, Category.EventID/Route.EventID → Event.EventID, EventEnrolment → User, Event and Category, and Result.EnrolmentID → EventEnrolment.EnrolmentID. The script uses CHECK constraints for small enumerations (roles, event/result/payment statuses), UNIQUE constraints for Email and BibNumber, and DEFAULTs such as GETDATE() for timestamping.
•	Seed data and examples: The script inserts sample rows to bootstrap the system: 4 users (2 organisers, 2 participants), 3 events, 5 categories, 3 routes, 4 enrolments and 2 results. These samples demonstrate typical relationships (organisers creating events, participants enrolling in categories) and provide test data for development or demo runs.
•	Usage and safety notes: Run the script in a non-production database (for example, a feature branch or local dev instance). Replace placeholder password hashes before any real deployment. The schema is intentionally simple—consider adding indexes (for large tables), transactional logic for payments, and stricter validation or nullable rules for production use.
•	Suggestions for extension: Add lookup tables for extensible enums (status/roles), unique constraints combining EventID/BibNumber to avoid cross-event collisions, stored procedures or parameterized APIs for enrolment/payment flows, and additional audit columns (CreatedBy, ModifiedAt) if you need traceability.
